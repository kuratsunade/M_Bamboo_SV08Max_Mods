# Hardware validation

The current candidate plan is [RC5 test plan](RC5_TEST_PLAN.md), also available [in Chinese](RC5_TEST_PLAN_CN.md). It supersedes the old EC2 manual recovery test sequence for RC5.

Current and historical results are separated in [Test Evidence](RC5_TEST_EVIDENCE.md). One natural QGL raw34 automatic recovery is recorded on the combined candidate; active rapid scan fault recovery and broader START_PRINT fault coverage remain open.

Use natural faults only. No wiring fault injection is requested. Healthy command success does not qualify a fault path. Observe the outer automatic owner before considering manual recovery.

A historical error code is not current health authority. Fresh transport evidence invalidates the failed transaction; a successful no motion recovery and, where needed, armed fresh Safe Home can restore trust. A historical fault sequence does not permanently prohibit drive current calibration once the trusted watermark has advanced through successful Z recovery. Newer faults block it again.

For current installation and restore blockers see [Validation](../VALIDATION.md).
